# ПОС · Преподавательская оценка студентов

Консольная ведомость для одного курса. Преподаватель заводит студентов и критерии, выставляет баллы и выгружает итог по группе. Нужен Go 1.22 или новее. Все зависимости входят в стандартную библиотеку.

## Запуск

Команды выполняются из корня проекта.

```bash
go run ./cmd/pos                        # демонстрация с экспортом в results.csv
go run ./cmd/pos --interactive          # работа с пустой ведомостью
go run ./cmd/pos --demo --policy graded # предварительный итог по сданным работам
go test -cover ./...
go vet ./...
```

Ведомость хранится в памяти до выхода. Меню поддерживает добавление, просмотр, изменение и удаление студентов и критериев. Повторная запись по паре ID студента и критерия исправляет оценку. Отменить оценку можно отдельно. Демо сохраняет отчёт в `results.csv`. Путь задаётся флагом `--export`.

## Расчёт итога

Итог по десятибалльной шкале равен взвешенному среднему долей набранных баллов, умноженному на 10.

```text
итог = 10 × Σ((балл / максимум) × вес) / Σ(вес)
```

При правиле `zero` учитываются веса всех критериев, пропуски дают ноль. При правиле `graded` в обе суммы входят только критерии с выставленной оценкой, включая явно выставленный ноль. Если оценок нет, итог равен нулю. Для расчёта нужен хотя бы один критерий.

## Доменная модель

| Понятие | Как работает в ведомости |
| --- | --- |
| Студент и критерий (`Student`, `Criterion`) | Сущности с постоянными ID. Можно переименовать студента или изменить вес критерия, сохранив связь с оценками. |
| Балл (`Score`) | Объект-значение. При создании проверяется диапазон от нуля до максимума критерия включительно. |
| Оценка (`Evaluation`) | Хранит балл и комментарий для пары «студент, критерий». Исправление заменяет прежнее значение. |
| Ведомость курса (`Course`) | Корень агрегата. В одном курсе доступны и рубрикатор, и оценки, поэтому можно проверить их согласованность перед записью. |
| Репозиторий (`CourseRepository`) | Загружает и сохраняет ведомость. Реализация в памяти хранит копию, изменения вступают в силу при сохранении. |
| Доменный сервис (`FinalScoreService`) | Считает итог из текущих весов и оценок. Исправление балла или веса учитывается при следующем запросе. |

Домен проверяет уникальность ID, наличие студента и критерия, допустимость балла и положительные конечные значения максимума и веса. При попытке снизить максимум ниже уже выставленного балла ведомость возвращает ошибку. При удалении студента или критерия она удаляет связанные оценки.

## Архитектура

Использована Ports and Adapters. Стрелка показывает, какой пакет импортируется.

```text
app (консоль) → application (сценарии и порты) → domain (правила ведомости)
repository (хранилище в памяти) → domain
export (запись CSV) → domain
cmd/pos → di, app
di → application, domain, repository, export
```

Все пакеты, кроме точки входа `cmd/pos`, находятся в `internal/`. Интерфейсы хранения и экспорта объявлены в `application/ports.go`. Адаптеры реализуют их обычными методами Go. В `di/container.go` контейнер передаёт реализации в конструкторы. В тесте `TestContainerInjectsPolicy` через тот же конструктор подставляется тестовая стратегия.

## Три паттерна

| Группа | Паттерн | Зачем нужен |
| --- | --- | --- |
| Порождающий | Простая фабрика, `EvaluationFactory.Create` | Находит максимум в рубрикаторе и проверяет балл до создания оценки. Выставление и исправление используют одну проверку. |
| Структурный | Фасад, `application.Service` | Меню вызывает `ExportResults` одной командой. Фасад получает текущие итоги и передаёт их экспортёру. |
| Поведенческий | Стратегия, `ScorePolicy` | На одних данных можно получить итог за курс или предварительный итог по сданным работам. Выбор задаётся флагом `--policy zero` или `--policy graded`. |

## Использование ИИ

Основой для структуры послужил проект ДЗ-1. ИИ участвовал в адаптации архитектуры под модель оценивания, написании кода и тестов. В числе рутинных задач были вывод таблиц в консоль и запись результатов в CSV.
